# SAHAJA YOGA — Claude Code project instructions

Read `SAHAJA_YOGA_MASTER_WEBSITE_PLAN.md` before planning, changing or generating UI. Its section 0 lists decisions already approved by the user; it takes precedence over earlier concepts.

## Hard rules
- Brand: **SAHAJA YOGA**, not only SAHAJA.
- KEEP the large floating ivory **3D lotus** in the existing approved hero.
- Replace ONLY the **small top-centre header symbol** with a permitted real photo of Shri Mataji; if a usable licensed photo is missing, use a clearly identified placeholder and request the approved image. The small top-left wordmark lotus stays.
- User's mantra counter: **10 taps per round**, never 12. The 11th tap begins the next round.
- All major screens, especially active meditation and mantra counting, must be exceptionally well designed. Minimalism is not a blank UI.
- Chakra worlds each get accurate Sahaja Yoga source-reviewed 3D forms, appropriately themed backgrounds, optional ragas and integrated tools. First perfect Vishuddhi: **blue / 16 petals / Raga Jayjayvanti**.
- Preserve source authenticity, media licensing, accessibility, privacy, functional reliability and responsive quality.
- Study `references/approved-current-hero.png` first, `references/replace-header-center-symbol.png` second, and treat `references/buttermax-composition-reference.png` as compositional inspiration only.

## Working process
1. Inspect existing repo and document what already works; don't overwrite success.
2. Write brief architecture and asset dependency plan.
3. Implement one phase at a time and test it.
4. Run the actual page, take desktop/mobile screenshots and critique composition; iterate.
5. Run automated counter/session tests and UX/accessibility checks.
6. Explicitly report assets or teachings awaiting licensing/content approval.

Don't stop at wireframes, mockups or a generic boilerplate website. Build the functioning web app.
